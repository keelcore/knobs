# Dependencies

## The Go package

| Module | Why |
| --- | --- |
| standard library | everything but YAML and JSON Schema |
| `go.yaml.in/yaml/v3` | YAML 1.2 decoding of the configuration files and YAML schemas; the YAML organization's continuation of `gopkg.in/yaml.v3` |
| `github.com/santhosh-tekuri/jsonschema/v6` | JSON Schema validation (drafts 2019-09 and 2020-12) of every schema and every value, and the check that a schema holds no keyword its draft does not define |
| `golang.org/x/text` | indirect: `jsonschema/v6`'s localized error messages |
| `golang.org/x/sys` | Windows only: the secrets file's owner and DACL (`perm_windows.go`) |
| `github.com/hectane/go-acl` | Windows tests only: files with a given DACL |

Dependencies are vendored (`vendor/`), so builds, tests and the pre-commit hook need no network. A new dependency
needs the owner's approval, a license on the allowlist (`make lint-licenses`), and no reachable vulnerability
(`make lint-vuln`).

## Pins

Every external input is pinned: Go modules by version, the Go toolchain by `go.mod`, actions by commit, images by
digest. `docs/current_pins.md` lists them, generated by `make generate-pins-doc`. `make update-pins` finds newer
eligible releases (no prereleases, a 14-day cooldown), verifies each, and with `APPLY=1` writes the passing pins for
review; open Dependabot pull requests and alerts are among its candidates (`docs/governance.md`, Dependency updates).
